# 核验 Trace 文献名与下降链设计

## 目标

只调整 `/api/verify_claim` 与 `/api/verify_claim/stream` 共用的 trace label，不改变四级检索的顺序、阈值、命中结果或提前停止逻辑。

## 文献命中摘要

`evidence_summary` 只能读取本次检索实际返回的 `evidence`：

- 按 evidence 原顺序提取 `(org, source_doc)`，按组合去重。
- 机构和文献名同时存在时显示为 `机构《文献名》`。
- 只有文献名时只显示 `《文献名》`；只有机构、没有文献名时不把机构计作一篇文献。
- 一篇时显示 `命中：机构《文献名》`。
- 多篇时显示首篇并追加 `等 N 篇`，例如 `命中：中国营养学会《中国居民膳食指南（2022）》等 2 篇`。
- 完全未命中时显示 `未命中已收录权威依据`。
- 若命中了依据但所有依据都缺少 `source_doc`，显示 `命中 N 条依据，未提供可展示的文献名`，不得补造文献名。

## 检索下降链

保留现有四级检索与命中即停：

1. 话题内结论库
2. 全库结论
3. 话题内全文块
4. 全库全文块

命中后追加一条说明事件：

- 前两级命中：`结论库命中，无需继续向下检索`
- 后两级命中：`全文库命中，无需继续向下检索`

四级均未命中时不追加命中说明，四条 miss 全部保留，之后由现有降级事件显示 `库中未收录相关权威依据，转为 AI 常识判断`。

新增说明事件只包含 trace 展示信息，不触发额外搜索，也不修改返回的 evidence、status 或 tier。

## 实现边界

- 新增一个纯格式化函数生成 evidence summary label，便于独立测试。
- 在 `search_evidence_for_claim` 的四个已有命中返回点前，复用一个小函数追加对应停止说明事件。
- SSE 继续通过现有 `on_event` 原样实时发送新增事件；同步接口继续从结果中的 `trace` 返回相同事件。
- 不改前端，不改证据数据，不改模型 prompt。

## 测试与验收

自动化测试覆盖：

- 同一文献多条依据只计一篇。
- 多篇文献只展示真实首篇并给出真实篇数。
- 缺失机构或文献名时不编造。
- 话题内/全库结论命中的停止 label。
- 话题内/全库全文命中的停止 label。
- 四级均未命中时四条 miss 完整且顺序不变。

最终运行：

- `python -c "import main"`
- 相关自动化测试及后端完整测试集。
- 真实调用 `/api/verify_claim/stream`，分别保存命中与未命中的 trace，确认真实文献名和下降逻辑可读。
