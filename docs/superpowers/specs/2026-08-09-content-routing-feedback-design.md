# FitProof 内容路由与输入反馈优化设计

## 背景

现有内容路由已经能在完整语音转写后识别健康无关视频，但仍有两个体验问题：

1. 一级元信息预检只依赖少量固定关键词，无法提前识别“Vibe Coding 个人网站”这类语义明确、但不在词表中的无关内容，导致系统先完成耗时的语音转写才停止。
2. 抖音首页、推荐页等非视频 URL 会进入媒体获取流程，最终被包装成“视频内容提取失败”，让用户误以为服务异常。
3. 成功识别为不在核验范围的结果目前显示为页面内黄色提示，结果感较弱。

## 目标

- 在音频下载、ASR 和关键帧处理前，通过快速元信息模型提前停止明确无关内容。
- 保持保守准入：无法确定时必须进入深度判断，不能因一级模型不稳定而误杀健康内容。
- 将内容范围拒绝结果改为用户已选择的 A 方案：居中结果弹窗。
- 在前端提交前和后端接口入口同时识别非视频链接，并给出明确的输入错误。
- 保留“减脂期我每天这样吃”等隐含健康方案的分析资格。
- 不提供“强制继续分析”入口。

## 两级内容路由

### 一级：快速元信息路由

执行位置：媒体平台信息获取成功后、音频下载和语音转写前。

输入仅包括：

- 标题
- 描述
- 平台分类
- 作者昵称（若平台返回）

一级使用快速模型和短输出预算，只允许返回：

- `stop`：元信息足以证明内容与健康信息核验无关。
- `continue_deep`：内容可能与健康相关，或信息不足以判断。

结构化结果：

```json
{
  "decision": "stop",
  "scope": "unrelated",
  "confidence": "high",
  "reason": "内容为网站开发教程",
  "quotes": ["如何 Vibe Coding 一个有设计感的个人网站"]
}
```

只有以下条件全部满足时才能提前停止：

- `decision` 为 `stop`
- `scope` 为 `unrelated`
- `confidence` 为 `high`
- `quotes` 中的文字确实存在于输入元信息
- JSON 结构和枚举全部合法

模型调用失败、输出不合法、置信度不足、引用不落地或信息模糊时，一级路由一律返回 `continue_deep`。现有固定格式词表可作为零成本明显案例优化，但不再承担通用主题识别职责。

示例：

- “如何 Vibe Coding 一个有设计感的个人网站” → `stop`
- “减脂期我每天这样吃” → `continue_deep`
- “足球运动员膝盖康复训练” → `continue_deep`
- “今天给大家看一个好东西” → `continue_deep`

上传文件通常只有文件名，不足以可靠判断，因此上传流程默认进入二级深度路由。

### 二级：转写与必要画面深度路由

一级放行后沿用现有深度流程：

1. 获取音频并完成语音转写。
2. 综合标题、描述和转写判断内容范围。
3. 只有动作、食物、报告或图表等信息必须依赖画面时才提取关键帧。
4. 最终分类为：明确健康主张、隐含健康方案、只有健康场景、完全无关。

明确健康主张和隐含健康方案进入主张拆解；只有健康场景和完全无关返回拒绝结果。

## 非法视频链接识别

采用前后端双重校验。

前端在进入加载页之前校验和提取链接，仅接受明确的视频地址：

- `https://v.douyin.com/<短链标识>/`
- `https://www.douyin.com/video/<数字视频ID>`
- 兼容平台已支持的标准视频分享域名与路径

以下地址直接判定为非视频链接：

- 抖音首页
- `?recommend=1` 等推荐页
- 搜索页、用户主页、频道页
- 其他网站 URL

前端在输入框下显示：

> 这不是具体的抖音视频链接，请粘贴视频分享链接或 `/video/数字ID` 地址。

此时不进入加载页，也不发起网络请求。

后端对 `/api/analyze_single` 使用相同语义再次校验。绕过前端的非法输入返回 HTTP 400 和相同含义的错误，而不是进入媒体获取后返回 502。真正的媒体平台故障、链接失效或网络错误仍返回内容提取失败。

## 拒绝结果弹窗

采用用户选择的 A 方案：居中结果弹窗。

### 完全无关

- 标题：`暂不支持分析这段视频`
- 说明：`识别为网站设计教程，不属于健康信息核验范围。`
- 识别依据：展示一条由路由器提供且经过原文校验的标题或转写引用。
- 主按钮：`换一个视频`

### 只有健康场景

- 标题：`这段视频暂无可核验的健康说法`
- 说明：内容可能涉及饮食、运动或生活记录，但没有发现明确健康主张或可模仿方案。
- 主按钮：`换一个视频`

弹窗使用遮罩、对话框语义、初始焦点和 Esc 关闭；点击主按钮后回到干净的输入状态。弹窗不展示“仍要分析”按钮。

非法链接属于输入校验错误，继续使用输入框附近的内联提示，不使用结果弹窗。

## 数据流

```text
用户粘贴内容
  → 前端提取并校验具体视频 URL
  → 后端再次校验 URL
  → 获取平台元信息
  → 快速元信息路由
      → 明确无关：rejected → 居中弹窗
      → 相关或不确定：语音转写
          → 深度内容路由
              → accepted：拆解健康主张
              → rejected：居中弹窗
```

## 错误处理

- 非视频 URL：400，明确提示链接类型错误。
- 一级模型失败或结果不可靠：放行到二级，不向用户报错。
- 二级模型无法形成合法、可落地结果：503，提示暂时无法判断并允许重试。
- 平台媒体获取或 ASR 失败：保留现有服务错误提示，并建议上传本地视频。
- 成功判断为范围外内容：200 `rejected`，弹窗展示，不视为系统错误。

## 测试

### 后端

- 快速元信息路由能提前拒绝 Vibe Coding 网站教程。
- 健康关键词和模糊标题必须放行到深度路由。
- 快速模型异常、低置信度、非法引用和非法 JSON 均放行。
- 一级拒绝时不调用 ASR、视频下载或关键帧流程。
- 首页和推荐页返回 400；标准短链和 `/video/数字ID` 通过。

### 前端

- 首页、推荐页及普通网页链接在提交前显示输入错误，不进入加载状态。
- 分享文案中的有效短链可以被正确提取。
- `rejected/unrelated` 和 `rejected/health_context_only` 展示对应弹窗文案。
- 弹窗主按钮恢复干净输入状态，且不存在强制继续入口。
- 生产构建、现有前端测试和移动端几何检查继续通过。

## 非目标

- 不扩展到 TikTok、快手、小红书等其他平台。
- 不允许用户绕过范围判断强制分析。
- 不用一级元信息模型判断健康说法真伪。
- 不改变后续证据检索、风险分层和报告生成逻辑。
